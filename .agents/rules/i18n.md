# Internationalization (en / es)

Locale files: `StayCare/src/i18n/en.json` and `StayCare/src/i18n/es.json`.

## User-facing content

- All user-facing text uses vue-i18n (`t(...)` / `$t(...)`): templates,
  buttons, modals, toasts, forms, validation messages, empty states.
- Every new key exists in **both** files with the same hierarchy.
- Preserve interpolation variables exactly (`{count}`, `{name}`, …).
- Natural translations and consistent business terminology.

## Do not translate

API property names, DB values, enum/status values, role codes, route names,
technical identifiers. Translate only their **labels**.

## Safe modification

Before renaming, moving or deleting a key:

1. Search all usages (including dynamic keys like `` t(`status.${s}`) ``).
2. Confirm no other context uses it with a different meaning.
3. Update every valid reference.
4. Compare the key structure of both locale files afterwards.

Do not remove duplicate-looking keys only because values are similar.
Do not change business logic while fixing translations unless strictly
necessary (explain why).

## Audit checklist

Missing keys · keys in one locale only · hardcoded strings · English shown in
Spanish (and vice versa) · wrong fallbacks · inconsistent terminology ·
mismatched interpolation variables · keys rendered literally in the UI.
